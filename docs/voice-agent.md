# AssemblyAI Voice Agent integration

The Workers adapter connects to AssemblyAI’s Voice Agent API. AssemblyAI manages transcription, turn detection and speech generation; its stored agent calls Nebius Token Factory for text generation using `nvidia/Nemotron-3_5-Lightning`. The model does not itself synthesize audio. This transport has synthetic protocol tests; those tests do not verify an account’s live model access, streamed tool behavior or recording controls.

## Create the stored agent

Run `node scripts/setup-voice-agent.mjs` to inspect a redacted dry run. It does not read env files or make requests. The optional `--apply` command creates a resource only when explicitly run, using `ASSEMBLYAI_API_KEY` and `NEBIUS_API_KEY` already present in the process environment. The repository task has not run `--apply`.

Creation stores the Nebius credential with AssemblyAI. The payload contains one custom LLM entry with base URL `https://api.tokenfactory.nebius.com/v1`, the exact model ID, 24 kHz mono PCM input/output, no greeting, and an inert initial prompt. A per-call prompt and tools replace the initial configuration before mic audio can pass. AssemblyAI’s REST create-agent request uses the API key in `Authorization`; WebSocket authentication uses its documented Bearer form. [Create an agent](https://www.assemblyai.com/docs/voice-agents/voice-agent-api/create-agent), [Custom LLM configuration](https://www.assemblyai.com/docs/voice-agents/voice-agent-api/connect-your-own-llm).

The script prints only the created ID and next steps. It never prints the returned provider object or credential. An ambiguous response requires checking the provider dashboard before retrying, because another POST may create a duplicate. A creation response is not live verification. Record the agent ID and an operator-reviewed configuration revision; no provider version is inferred from an undocumented response field.

## Session protocol

`connectVoiceAgent(options, callbacks)` returns a Workers-native session with `send`, `requestReply`, `interrupt`, `update`, `close`, `ready` and `sessionId`. First it sends only `session.update.session.agent_id`. On `session.ready`, it exposes the session identity for durable cleanup, validates the resolved PCM formats and Nebius model/base URL, then sends the mutable prompt/tools. Audio remains blocked until `session.updated` confirms the expected prompt/tools and audio configuration. Missing or mismatched echoes fail closed. A 10-second configuration deadline bounds an incomplete handshake. No initial greeting is permitted. [Deployment](https://www.assemblyai.com/docs/voice-agents/voice-agent-api/deploy), [WebSocket events](https://www.assemblyai.com/docs/voice-agents/voice-agent-api/events-reference).

Input is raw PCM16 little-endian at 24 kHz, in real-time chunks of at most 100 ms; the caller uses 50 ms. Output is decoded from base64 with a one-second per-event cap. Odd trailing bytes are carried to the next chunk of the same reply; an incomplete sample at normal completion fails closed. No raw audio or resume credential is persisted by the adapter. Mic audio is never buffered before readiness. Session totals, text, tools and individual events have finite limits. [Audio contract](https://www.assemblyai.com/docs/voice-agents/voice-agent-api/audio-format).

Final caller items and agent replies are deduplicated by their provider IDs. Every callback carries the provider session ID where relevant. User partial transcripts replace prior partial text. Tool reply IDs use the documented `fc-` prefix and never become playable agent replies. Tool callbacks execute without blocking receipt of `reply.done`; only the matching completed reply at an idle event boundary permits sending its result. Duplicate call IDs execute once; reuse with different arguments fails. Results completing after interruption or a new reply are discarded, while the durable application receipt retains any already-committed effect. Tool exceptions are returned as generic errors, without provider or credential text. [Client tools](https://www.assemblyai.com/docs/voice-agents/voice-agent-api/tools/client-side-tools).

`interrupt()` immediately gates output locally and drops pending audio bytes. Caller speech and interrupted reply events invalidate playback through the application callbacks. There is no invented provider cancel event. `close()` sends `session.end` and closes a known session. If closure occurs before its ID arrives, the adapter blocks all conversation activity and uses the remainder of the original 10-second handshake deadline to obtain the ID before ending it. On ownership changes the application closes the provider session. Audio messages in the documented API do not include a reply ID, so association relies on ordered WebSocket delivery between `reply.started` events. Explicit foreign IDs are rejected if supplied; arbitrary interleaving without IDs cannot be distinguished. NurseBridge does not automatically reconnect the provider; it requests nurse help. A new fictional call is needed for new automated intake.

## Recording, deletion and live activation

AssemblyAI documents automatic session recordings, transcripts and configuration history. Its current `DELETE /v1/sessions/{id}` operation returns 204 and soft-deletes the session, making it absent from listings and its artifacts inaccessible. `deleteVoiceAgentSession` implements that authenticated request, treating 404 as already absent, with bounded timeout and sanitized errors. The Durable Object owns durable retry scheduling. `session.end` is session termination, not deletion. [Session history and deletion](https://www.assemblyai.com/docs/voice-agents/voice-agent-api/session-history#delete-a-session).

The inspected documentation does not establish a recording-disable control, retention duration, or physical backup erasure guarantee. Therefore NurseBridge’s account-retention gate remains closed; setting credentials, creating an agent or deleting a session does not satisfy it. Live activation requires verified provider recording/retention controls as well as the exact model and tool behavior. Until those requirements are resolved, use the fictional mock scenario. No real patient data is authorized by this setup documentation.

A connection can fail before the provider supplies a session ID. NurseBridge preserves a content-free attempt record (local attempt ID, agent ID, start time, reconciliation status) and reports that recording cleanup requires operator reconciliation. A restart also marks incomplete attempts for reconciliation. An operator must inspect the provider session history for the matching agent and time, establish identity, and apply the provider's deletion process; the app never guesses IDs or deletes unrelated sessions. Known session IDs remain in the durable cleanup retry table after case deletion. This uncertainty is another reason the live privacy gate cannot be enabled by an environment flag alone.

## Focused validation

`node --test scripts/setup-voice-agent.test.mjs` verifies dry-run isolation, the exact creation payload and safe errors. `vitest run --config apps/realtime/vitest.config.ts apps/realtime/tests/voice-agent.test.ts` exercises the production protocol in Workers, including a real local WebSocketPair upgrade, configuration gates, interruption, PCM boundaries, transcript/tool deduplication and logical deletion. All provider requests in those tests are mocked.
